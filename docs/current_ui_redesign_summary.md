# 工程检测项目管理系统现状总结（用于页面重设计）

## 1. 文档目的

这份文档用于总结当前系统的：

- 界面信息架构
- 页面布局与共用组件
- 现有功能模块
- 关键业务流程
- 当前交互痛点与重设计切入点

目标不是描述“理想状态”，而是尽量还原**当前已经做出来并可运行**的桌面端系统，方便后续重新设计页面时不丢功能、不丢流程。

---

## 2. 系统定位

当前系统本质上是一个面向**工程检测公司内部使用**的桌面端业务系统，主要覆盖：

- 工作记录导入与维护
- 合同识别、合同价目项维护
- 产值计算与报表展示
- 基础主数据维护
- 模型 API 管理
- 数据备份与健康状态查看

当前不是多角色 SaaS，也不是移动端产品。更接近：

- 单机/内网桌面业务系统
- 数据录入 + 数据核对 + 数据汇总的复合后台

## 3. 当前信息架构

### 3.1 主导航

左侧固定侧边栏，当前主要导航如下：

#### Command Layer

- 控制台 `/`
- 工作记录 `/worklog`
- 产值报表 `/reports`
- 数据安全与备份 `/nexus`

#### Data Fabric

- 合同管理 `/contracts`
- 人员管理 `/master/staff`
- 项目管理 `/master/projects`
- 单价管理 `/master/prices`
- 模型 API 管理 `/master/models`

### 3.2 当前导航特点

- 侧边栏为固定宽度桌面布局
- 页面切换是典型后台应用结构，不是多层级流程式导航
- 当前层级偏平，没有面包屑
- 每个页面基本都独立承担完整任务

## 4. 当前全局布局与界面框架

### 4.1 全局布局

全局布局定义在：

- `src/src/app/layout.js`
- `src/src/components/Sidebar.js`
- `src/src/app/globals.css`

当前整体结构是：

- 左侧固定导航栏
- 右侧主内容区纵向滚动
- 页面顶部统一 `page-header`
- 页面主体统一 `page-body`

### 4.2 当前共用布局模式

目前几乎所有页面都复用以下模式：

1. 页面头部
   - `page-kicker`
   - `h2` 页面标题
   - `page-desc` 页面说明
   - 右侧操作按钮区

2. 指标卡区域
   - 一般 4 张 `metric-card`
   - 用于概览数量、状态、进度、覆盖范围

3. 功能区
   - 表单卡片 `card`
   - 图表卡片 `chart-panel`
   - 表格容器 `table-shell`
   - 筛选容器 `filter-bar`

4. 详情或二级操作
   - 部分页面使用弹窗
   - 部分页面使用页面内嵌表单

### 4.3 当前视觉风格

当前已经切成一版偏浅色液态玻璃风：

- 浅灰白背景
- 半透明玻璃卡片
- 蓝色主按钮
- 蓝灰色辅助信息
- 橙色作为强调/警示辅助色

当前主题关键词可以概括为：

- Desktop
- Glass / Liquid
- Data-heavy
- Dashboard / Admin Console

## 5. 页面逐页总结

## 5.1 控制台 `/`

### 作用

作为全系统总览页，承担：

- 关键指标概览
- 最近动态查看
- 快速进入核心任务
- 快速录入工作记录

### 当前布局

- 顶部：页面标题与说明
- 第一屏：4 张指标卡
  - 注册人员
  - 项目总数
  - 累计工作记录
  - 合同归档数
- 中间：左右双栏
  - 左：人员产值趋势图
  - 右：最新工作动态
- 底部：快速开始按钮区
- 弹窗：快速录入工作记录

### 当前交互

- 指标卡可点击跳转对应模块
- 最新工作动态可点击跳到工作记录页
- 快速开始按钮跳转到核心操作
- 可在控制台直接打开“录入每日工作”弹窗

### 当前价值

- 是最像“运营控制台”的页面
- 适合作为后续重设计中的核心展示页

---

## 5.2 工作记录 `/worklog`

### 作用

这是目前最核心的业务录入与处理页面之一，负责：

- Excel / WPS 工作记录导入
- 粘贴文本导入
- 导入结果反馈
- 面积合同占比确认
- 工作记录筛选、编辑、删除
- 批量删除

### 当前布局

- 顶部：页面标题 + 当前可见记录/金额摘要
- KPI 区：工作记录、工作量、待确认占比、未签合同数量
- 中部左右区块：
  - 左：Excel 文件导入
  - 右：WPS 粘贴导入
- 导入结果卡片：
  - 成功数量
  - 扩展项数量
  - 待确认占比数量
  - 错误列表
  - 新项目快捷入口
- 筛选条：
  - 项目
  - 人员
  - 日期
  - 搜索
- 工作记录表格
- 编辑弹窗
- 面积合同占比确认弹窗

### 当前能力

- 支持 `.xlsx / .xls`
- 导入后会自动尝试计价
- 如果识别到新项目，会自动建项目台账
- 如果导入后出现新项目，页面会直接提供“上传并关联合同”按钮
- 支持批量选择删除工作记录
- 支持手工指定总产值

### 当前重要业务逻辑

- 无合同也会保留工作量
- 面积合同不会直接按单价计价，而是进入“占比确认”
- 新项目可以直接跳合同页完成上传和关联

### 当前重设计重点

- 导入结果区信息量大但层级偏平
- 导入、筛选、表格、编辑、占比确认都堆在一个页面里
- 后续重设计可以考虑把“导入态”和“台账态”更清晰分离

## 5.3 合同管理 `/contracts`

### 作用

负责合同识别、合同复核、价目项维护、项目关联，是当前第二个核心业务页。

### 当前布局

- 顶部：页面标题、说明、刷新、手动新建
- 指标卡：
  - 已归档合同数
  - 检测价目项数
  - 已关联合同项目数
  - 待确认缓存数
- 中部双栏：
  - 左：批量导入合同
  - 右：单份合同识别与复核
- 中下：合同确认与编辑表单
- 底部：合同列表与展开详情

### 当前能力

- 单份合同上传识别
- 批量合同导入
- 批量导入后不自动入库，而是先缓存、逐份确认
- OCR 识别结果带入表单
- 支持按单价/按面积计价
- 支持维护价目项
- 支持项目关联
- 可从工作记录页或项目页带着项目跳转进来，并自动预选关联项目

### 当前关键流程

#### 单份合同流程

1. 上传文件
2. OCR 识别
3. 打开确认表单
4. 人工修正合同字段与价目项
5. 保存入库
6. 若带有预选项目，则自动关联合同与项目

#### 批量合同流程

1. 批量上传
2. 后台任务逐份识别
3. 每份先进入缓存
4. 用户逐份点击“载入确认”
5. 保存后才正式入库

### 当前重设计重点

- 当前页面承担“批量任务中心 + 单文件上传 + OCR 结果展示 + 表单编辑 + 合同列表”，信息密度极高
- 后续可以考虑拆成：
  - 任务中心
  - 合同复核工作台
  - 合同档案列表

## 7. 当前关键业务流程

## 7.1 工作记录导入流程

1. 用户导入 Excel 或粘贴文本
2. 系统解析并拆分记录
3. 自动创建新项目/新人员（如果不存在）
4. 自动尝试产值计算
5. 如果是面积合同，进入占比确认
6. 导入结果展示成功数、错误数、新项目入口

## 7.2 新项目 -> 合同关联流程

1. 工作记录导入后识别到新项目
2. 用户点击“上传并关联合同”
3. 跳到合同页并自动预选该项目
4. 用户上传合同
5. OCR 填表
6. 保存时自动建立合同与项目关联

同样，这条链也可从项目管理页直接发起。

## 7.3 合同批量导入流程

1. 批量上传合同文件
2. 后台队列逐份识别
3. 每份文件先缓存结果
4. 用户逐份载入确认
5. 点击保存后才正式入库

## 7.4 面积合同产值流程

1. 工作记录命中面积合同
2. 系统不直接给出单价
3. 弹出占比确认
4. 用户输入本次检测占比
5. 系统按合同金额 x 占比生成产值

## 9. 当前界面问题 / 重设计切入点

## 9.1 信息密度过高

尤其是：

- 工作记录页
- 合同管理页

单页同时承担：

- 导入
- 结果反馈
- 编辑
- 列表
- 业务确认

容易造成认知负荷过高。

## 9.2 业务状态与页面结构没有完全对齐

例如合同管理页目前同时包含：

- 批量任务中心
- 单文件 OCR
- 复核表单
- 合同档案列表

这些其实是 4 种不同工作场景。

## 9.3 共用结构统一，但辨识度还不够

很多页面长得相似：

- 顶部说明
- 4 张卡
- 表单
- 表格

对熟悉用户来说上手快，但对重设计来说，也说明页面缺少更强的任务导向差异。

## 9.4 主次层级还可以继续优化

后续重设计时建议更明确区分：

- 总览页
- 录入页
- 核对页
- 管理页
- 系统页

## 11. 重设计建议方向

如果后续你要重新设计页面，建议按下面的结构去想，而不是只做换皮：

### 11.1 把系统拆成 4 类页面

1. 总览型
   - 控制台
   - 报表

2. 录入型
   - 工作记录导入
   - 单份合同上传

3. 核对型
   - 合同复核
   - 面积合同占比确认

4. 台账型
   - 人员
   - 项目
   - 单价
   - 模型入口

### 11.2 重点重做的优先级

推荐优先级：

1. 合同管理页
2. 工作记录页
3. 控制台
4. 报表页
5. 主数据页

### 11.3 设计目标建议

- 让“导入”和“核对”分层
- 让“当前任务”比“全部信息”更突出
- 减少一个页面里同时出现太多密集模块
- 让操作路径更短
- 让错误、待确认、完成三种状态更明确

## 13. 一句话总结

当前系统已经不是“原型后台”，而是一个**以工作记录、合同识别、产值计算为核心的桌面工程检测业务系统**。  
如果要重新设计页面，最值得做的不是单纯换视觉，而是把“导入、核对、台账、总览”这四类任务重新拆清楚。
